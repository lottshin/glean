# Glean 生词库

Glean 使用普通 Markdown 作为唯一权威数据。插件卸载后，词条、释义、语境和来源仍然可以直接阅读和搜索。

## 文件布局

新卡片按首字符放入固定的一层目录：

```text
Glean/Words/
  a/abandon.md
  b/bracket.md
  g/go.md
  0-9/3d.md
  _/其他字符开头的词.md
```

分桶只用于避免 Obsidian 文件列表一次渲染几千个兄弟节点，不参与词义查询。路径由 lemma 直接计算，运行时不会遍历磁盘查找单词。

旧版扁平卡片仍可读、可更新。Glean 不会在启动时自动移动用户文件；需要整理时，在命令面板运行“Glean: 整理生词目录”，确认预检数量后再执行。整理结果写入 `_migration-report.md`。

## Frontmatter

- `glean: true`：Glean 卡片标记。
- `uid`：永久卡片标识。未来导出 Anki 时用于幂等更新，创建后不应修改。
- `lemma`：规范词形，也是逻辑主键。
- `forms`：实际遇到的屈折形式，不使用 Obsidian 全局 `aliases`，避免污染快速切换和链接补全。早期版本把词形写在 `aliases` 里；这些卡片在下次保存时会把 `aliases` 的内容并入 `forms` 并移除该字段，因此如果你曾手动给生词卡加过 Obsidian 别名，它也会被一并转成词形。
- `status`：`new`、`learning`、`known` 或 `ignored`，可在查词弹层中切换。
- `sources`：出现过的来源媒体或来源笔记 wikilink。
- `created` / `updated`：创建和最后有效变更日期。

查词弹层里，已入库的词可以切换学习状态，也可以点「打开笔记」或「移出生词」。打开生词笔记后，标题栏有垃圾桶按钮，正文顶部也有「移出生词」。也可以在文件列表右键，或用命令面板「Glean: 移出生词」。Glean 会把对应笔记移到 Obsidian 的废纸篓（不是永久删除），所以误点可以找回。助记、自定义段落会随文件一起走。

如果目录中出现多张 lemma 相同的卡片，Glean 会提示冲突并稳定选择路径排序靠前的一张，不会在用户不知情时随机切换目标。应先手动合并卡片，再继续入库或移出操作。

## 性能模型

Glean 等待 Obsidian metadata cache 就绪后，只遍历生词目录中的文件元数据建立内存 catalog，不读取笔记正文，也不扫描 vault 里的其他 Markdown。后续新增、修改、删除和重命名均通过事件增量更新。

- 查询 lemma：平均 `O(1)`。
- 首次建立 catalog：`O(W)`，其中 `W` 仅为生词卡数量。
- 正常保存：一次原子文件写入。
- 无变化的重复保存：零写入。

五千张卡片是设计目标范围。两万张卡片时，Glean 的内存索引仍然很小，但 Obsidian 首次索引和云盘同步大量小文件可能明显变慢；这是 vault 和同步层的成本。关系图谱建议排除 `Glean/Words`。

## 阅读

Glean 阅读是显式模式。进入后正文保持连续；单词可点，代码和链接不动。状态栏只出现在阅读视图顶部一条，不插入段落之间。

图标统一用麦穗:侧边栏那枚代表插件本身，标题栏那枚代表「对这篇笔记启用 Glean」。笔记上 Glean 只有阅读这一个动作，所以不需要第二个字形来区分，一个品牌标记走到底。麦穗同时避开了 Obsidian 原生阅读视图切换按钮的 `book-open`，两者不会看成重复按钮。

状态栏不再显示推测的“认识百分比”。文本难度采用固定口径：按全文词次统计 BNC / FRQ 排名前 3000 的覆盖率；“本文生词”只统计当前文章中确实以 `new` 或 `learning` 状态入库的唯一词。两项数据都不需要冷启动，也不会把未操作的词假定为认识或不认识。

设置中的“阅读词汇提示”按 BNC / FRQ 排名给未入库的较难词加轻量虚线，可选常用 3000、5000、8000 词以外或关闭。这个选项只影响渲染，不改变状态、不创建 Markdown 文件。已掌握和忽略的词不染色；`new` / `learning` 继续用状态底线区分。点词仍走同一套弹层和生词库。

同一篇笔记可以同时开在多个面板。只有当它的所有面板都不在阅读视图时，Glean 才退出阅读模式，因此在旁边开一个源码面板不会打断阅读。

## 整句解析

点词是瞥一眼，整句是一段会话，因此两者用不同的容器。查词用浮层，点别处就走；整句解析停靠在 `.markdown-reading-view` 这个 flex 容器里，作为预览区的兄弟节点，正文让出宽度而不是被覆盖。窗口窄于 900px 时改为底部停靠。

生命周期是显式的：只有点「解析选区」或运行命令才打开；打开后由 `selectionchange` 跟随新选区换内容，折叠选区（点词）不触发；只有 Esc、面板关闭按钮、再次点击工具栏按钮、退出阅读模式或视图销毁才关闭。滚动不再是关闭手势——浮层时代因为锚点会失效才需要滚动即关，停靠之后这个理由不成立。

逐词释义完全离线：先按停用词表过滤虚词，再用词典的屈折表把不同词形归到同一 lemma，同一 lemma 只出一条，按首次出现顺序排列，单次最多 80 条。面板里的「加入」重新走一次词典查询后建卡，语境是整段选区。

为了不打断阅读，面板开着时不重绘正文；关闭面板时才统一刷新染色和覆盖率。换句会清空上一句的译文和入库状态，避免译文和正文对不上。

## 在线翻译边界

在线翻译是唯一会联网的功能，默认关闭，且只在用户点击时发出单次请求。划选和换句都不会触发翻译，面板跟随选区时只重跑离线释义。请求内容仅为当前选区，不含生词库、笔记路径或其他 vault 数据。超过 4000 字直接在本地拒绝，避免误发整篇文章。服务无响应时 30 秒超时，面板回到可重试状态，离线释义不受影响。

API key 存在插件的 `data.json` 里，是明文。这是 Obsidian 插件设置的通用形态，但意味着共享 vault 或同步仓库时会一并带走，文档和设置项都对此明确提示。

## Anki 边界

Glean 始终拥有 Markdown 原始数据，Anki 只负责可选的复习调度。未来导出以 `uid` 为稳定键，支持重复导出时更新已有卡片；不把 Anki 数据库作为主库，也不做双向状态同步。
