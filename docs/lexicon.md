# Echo 生词库

Echo 使用普通 Markdown 作为唯一权威数据。插件卸载后，词条、释义、语境和来源仍然可以直接阅读和搜索。

## 文件布局

新卡片按首字符放入固定的一层目录：

```text
Echo/Words/
  a/abandon.md
  b/bracket.md
  g/go.md
  0-9/3d.md
  _/其他字符开头的词.md
```

分桶只用于避免 Obsidian 文件列表一次渲染几千个兄弟节点，不参与词义查询。路径由 lemma 直接计算，运行时不会遍历磁盘查找单词。

旧版扁平卡片仍可读、可更新。Echo 不会在启动时自动移动用户文件；需要整理时，在命令面板运行“Echo: 整理生词目录”，确认预检数量后再执行。整理结果写入 `_migration-report.md`。

## Frontmatter

- `echo: true`：Echo 卡片标记。
- `uid`：永久卡片标识。未来导出 Anki 时用于幂等更新，创建后不应修改。
- `lemma`：规范词形，也是逻辑主键。
- `forms`：实际遇到的屈折形式，不使用 Obsidian 全局 `aliases`，避免污染快速切换和链接补全。早期版本把词形写在 `aliases` 里；这些卡片在下次保存时会把 `aliases` 的内容并入 `forms` 并移除该字段，因此如果你曾手动给生词卡加过 Obsidian 别名，它也会被一并转成词形。
- `status`：`new`、`learning`、`known` 或 `ignored`，可在查词弹层中切换。
- `sources`：出现过的来源媒体或来源笔记 wikilink。
- `created` / `updated`：创建和最后有效变更日期。

查词弹层里，已入库的词可以切换学习状态，也可以点「打开笔记」或「移出生词」。打开生词笔记后，标题栏有垃圾桶按钮，正文顶部也有「移出生词」。也可以在文件列表右键，或用命令面板「Echo: 移出生词」。Echo 会把对应笔记移到 Obsidian 的废纸篓（不是永久删除），所以误点可以找回。助记、自定义段落会随文件一起走。

如果目录中出现多张 lemma 相同的卡片，Echo 会提示冲突并稳定选择路径排序靠前的一张，不会在用户不知情时随机切换目标。应先手动合并卡片，再继续入库或移出操作。

## 性能模型

Echo 等待 Obsidian metadata cache 就绪后，只遍历生词目录中的文件元数据建立内存 catalog，不读取笔记正文，也不扫描 vault 里的其他 Markdown。后续新增、修改、删除和重命名均通过事件增量更新。

- 查询 lemma：平均 `O(1)`。
- 首次建立 catalog：`O(W)`，其中 `W` 仅为生词卡数量。
- 正常保存：一次原子文件写入。
- 无变化的重复保存：零写入。

五千张卡片是设计目标范围。两万张卡片时，Echo 的内存索引仍然很小，但 Obsidian 首次索引和云盘同步大量小文件可能明显变慢；这是 vault 和同步层的成本。关系图谱建议排除 `Echo/Words`。

## 阅读

Echo 阅读是显式模式。进入后正文保持连续；单词可点，代码和链接不动。状态栏只出现在阅读视图顶部一条，不插入段落之间。覆盖率按全文唯一英文词统计，其中 `known` 和 `ignored` 都计入“认识”。已掌握和忽略的词不染色；`new` / `learning` 用底线区分。点词仍走同一套弹层和生词库。手动切换回源码模式时，Echo 会退出阅读模式，避免界面显示为已启用但无法点词。

## Anki 边界

Echo 始终拥有 Markdown 原始数据，Anki 只负责可选的复习调度。未来导出以 `uid` 为稳定键，支持重复导出时更新已有卡片；不把 Anki 数据库作为主库，也不做双向状态同步。
